药品进销存月报助手

一个纯前端、离线、单文件的工具，帮妈妈把多家「供应商服务系统」导出的表格整合与对账，自动生成月度进销存报告。

交付形态：单文件 HTML（离线可用）+ 桌面 ZIP 技术：SheetJS 内联解析 .xls/.xlsx 无后端 · 无联网 · 数据不出本机

01项目缘起

妈妈的每月手工流程：登录多家商业公司各自的系统 → 每个系统导出 4 张表 → 手工整理、对账、排查差异。

妈妈是供应商侧，每月要对接多家商业公司（南京药业、南京医药苏州恒昇、江苏华晓、南通健桥……）。每家都有一套独立的「供应商服务系统」，每套系统要导出 购进、销售、期初、期末 4 张表。几十张表的手工合并和对账，是她每月最耗时、最容易出错的一步。这个工具的目标，就是把「导出之后的整理 + 对账」全部自动化。

02业务模型

一条三级供应链，数据层层展开。

第 1 级

药品（10 种）

→

第 2 级

商业公司（13 家）

→

第 3 级

医院（各配本地区 N 家）

药先铺到商业公司，商业公司再配送到自己地区的医院。对账的粒度是「商品」，匹配靠 商品编码 / 客户编码（名称会不一致，不能拿名称匹配）；批号不参与对账。

03输入数据（4 张表）

每套系统导出 4 张表，工具自动识别类型并合并同类表。粉色底是妈妈在示例里标出的「她需要的列」。

表标题行列数粉色列（她需要的）
购进购进记录19商业公司、供应商、品名、规格、厂家、数量
销售销售记录26商业公司、供货商、客户、品名、规格、厂家、数量
期初 / 期末历史库存明细12供应商、品名、规格、厂家、数量、商业公司

粉色列的规律就是「谁 + 什么药 + 多少」：商业公司 / 供应商(供货商) / 客户 / 品名 / 规格 / 厂家 / 数量，另加「单位」。没标粉的（商品编码、日期、批号、价格、金额…）是系统自带的辅助列——但商品编码和日期对账时仍要用，所以工具内部完整保留，只在展示/导出时按「粉色列 + 单位」呈现。

04核心对账规则

差异 = 期末明细 − 期初明细 − 本月入库 + 本月出库
按「商品」对账（不按批号）；退货在购进/销售里是负数，已自动抵扣；单位是盒 / 支（同一商品编码内部一致）。

05开发历程

从初版到交付的完整时间线。

  1. 阶段一

    初版成型

    两个板块：「进销存核对」做对账与差异排查，「销售跌涨幅对比」做上月 vs 下月的销量对比。单文件、离线、无后端。

  2. 阶段二

    交互打磨

    导出按钮移到右上角；跌涨幅改为按「销售数量」而非金额；涨幅与跌幅分两列展示；dashboard 显示对比时间并改为空态常显。

  3. 阶段三

    真实数据接入

    读懂 4 份真实 .xls，确认三类表结构与粉色列含义；发现公司列名叫「商业公司」，而月报当时只认「公司/机构」，导致识别不到公司。

  4. 阶段四

    月报升级

    月报识别「商业公司」列；期初/期末靠文件名关键字「期初/期末/期未」自动区分；dashboard 增加「医院明细数」（按 产品+商业+医院 计数）。

  5. 阶段五

    新增「数据整理」板块

    放在月报前面，专门把不同系统的同类表合并：自动分类、按列名别名归一化、保留粉色列 + 单位，可下载 4-sheet Excel，也可一键推送到月报。

  6. 阶段六

    打包交付

    用 Python zipfile 以 UTF-8 文件名打包成离线 ZIP，解压即用。

06最终产出（三个板块）

①

数据整理

多系统同类表合并，输出干净的粉色列 + 单位台账；可下载、可推送月报。

②

进销存核对

核查日期、差异对账、dashboard、缺失文件弹窗、历史记录、带底色导出。

③

销售跌涨幅对比

上月 vs 下月按销售数量对比，涨幅/跌幅分列，dashboard 显示对比月份。

交付物：index.html（离线双击可用）＋ 桌面 药品进销存月报助手-离线版.zip。

07技术实现要点

  • 纯前端单文件，SheetJS（xlsx）内联，直接解析 .xls / .xlsx，无需网络与后端，数据不出本机。
  • 列名用「别名归一化」跨系统对齐（如公司 = 商业公司 / 公司 / 机构；客户 = 客户 / 医院）。
  • 粉色列作为「需要的列」的约定，导出时只保留粉色列 + 单位。
  • 历史记录存 localStorage（在 Safari file:// 下可能失效，属已知限制）。
